x86-64 · UEFI · NativeAOT · CC0

An operating system written entirely in C#.

Bootloader, kernel, garbage collector, drivers, shell and applications. The kernel, DOOM and the shell are pure C#: not a single .c, .h or .asm file. Stock PowerShell 7 runs on top of that through an optional CoreCLR fork, which is the one C++ component and lives in a separate submodule.

Invariant #1

    
Every line of source is C#, even the parts you would normally write in assembly.

    
MSBuild and PowerShell only orchestrate the build. Interrupt handlers, write barriers, interface dispatch trampolines, reading CR3: each is solved one of three ways. Tiers 0 and 1, the kernel and every native app, contain zero lines of C, C++ or assembly. The only exception is Tier 2: stock PowerShell needs a JIT and reflection, so it runs on an optional CoreCLR fork, which is C++ and is not required to build or boot the system. As far as we know, no other managed OS holds this invariant: Cosmos drops to X#, its own assembler dialect, for the lowest layer, and Singularity kept its bootstrap and HAL in C++ and assembly. If a task looks impossible in C#, it has been framed wrong.

    

      

        
1 · The language itself

        
Plain C#

        
[RuntimeExport], [UnmanagedCallersOnly], delegate* unmanaged, fixed, pointer arithmetic.

      

      

        
2 · Machine code from C#

        
Iced assembler, at build time and at runtime

        
A source generator bakes 16 early-boot stubs into byte templates. Once the heap is up, Iced is called directly.


var a = new Assembler(64);
a.mov(rax, rcx);
a.Assemble(writer, rip);

      

      

        
3 · Symbols from attributes

        
COFF objects without a line of C

        
When the linker needs a symbol ILC does not emit, an MSBuild task generates the .obj itself.


[BootAsm.CoffDataSymbol(
    "__security_cookie",
    Section = ".data")]
public static ulong SecurityCookie
    = 0x2B992DDFA232UL;

      

    

  






  

    
Architecture

    
Three execution tiers

    
From bare metal up to stock .NET assemblies loaded byte-for-byte. A unikernel: one address space, its own scheduler, its own GC.

    

      

        
Tier 0

        
Kernel-AOT

        
Kernel, boot, drivers, scheduler. Direct access to CR3, PCI, MMIO, IDT, local APIC.

        
Lives in
OS/
Built with
NativeAOT + NoStdLib + MinimalRuntime

      

      

        
Tier 1

        
PE app

        
Freestanding apps: launcher, shell, DOOM, NES emulators. Each one gets its own collector and heap.

        
Lives in
apps_native/
Built with
NativeAOT + NoStdLib + shared SDK

      

      

        
Tier 2

        
CoreCLR-hosted

        
Stock .NET DLLs, byte-for-byte: JIT, reflection, the full BCL. This is how PowerShell runs.

        
Lives in
\sharpos\*.dll on FAT
Built with
optional CoreCLR fork (C++), linked into the kernel

Pipes

    
Programs pass objects, not bytes.

    
PIPEGEN | PIPEFILT 3 | PIPECNT works just like in bash, but every stage receives a real object with fields. It lives in shared exchange memory: no parsing, no copying into the receiver's heap.

    

      

        
›PIPEGEN 1000LogEntry × 1000

        

        
?PIPESPY a@ 0x7F3A2000

        

        
?PIPESPY b@ 0x7F3A2000

        

        
ƒKQL 'where Level >= 3 | summarize n = count() by Level'

        
Both PIPESPY stages report the same address: one object flows through four programs without being copied.

      

      
    
        
  • Zero allocations per messageCopy, forward, read in place. On a 100-object graph it is 5–6× faster than BinaryWriter + BinaryReader.
    • 
        
  • Queries right in the pipelineKusto Query Language over a message stream: where, summarize, extend, project. The query binds before the first data arrives.
    • 
        
  • One attribute and a type can travelMark a type with [Message] and it can be read, filtered and written back without a copy.

    Pipe.Read<LogEntry>()
    .Where(e => e.Level >= min)
    .WriteTo();  // zero-copy
    • 
        
  • JSON, JSON Lines, CBORCONVERT is fully streaming with one message in memory: a 100 MiB file passes through a 64 MiB heap.

Quick start

    
Build it yourself

    
It builds with a plain dotnet publish -r win-x64. mise or nix installs the toolchain, and the image boots in QEMU.

    

      
    
        
  1. Install mise or nix. Every tool version is pinned in mise.toml and flake.lock.
    2. 
        
  2. Clone with submodules. The CoreCLR fork is optional; skip it with -SkipCoreClr.
    3. 
        
  3. Build and run. run_build.ps1 builds the kernel, makes the image and launches QEMU.
    4. 
        
  4. Drop in payloads. DOOM1.WAD, .nes cartridges and PowerShell go into payloads/.
    5. 
      

      

        

          
          
        

        

          

# macOS / Linux / Windows
brew install mise            # or: winget install jdx.mise

git clone --recurse-submodules \
  https://github.com/daniilvaino/SharpOS.git
cd SharpOS
mise trust && mise bootstrap
mise exec -- pwsh

# then, in PowerShell
./build.ps1 launcher
$env:SHARPOS_GUI=1; ./run_build.ps1 -UsbOnly -SkipCoreClr

        

        

          

# NixOS or any Linux with flakes enabled
git clone --recurse-submodules \
  https://github.com/daniilvaino/SharpOS.git
cd SharpOS
nix develop --command pwsh

# then, in PowerShell
./build.ps1 launcher
$env:SHARPOS_GUI=1; ./run_build.ps1 -UsbOnly -SkipCoreClr
