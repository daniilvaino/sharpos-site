Invariant #1

    
Every line of source is C#. Even the parts you'd normally write in assembly.

    
MSBuild and PowerShell only orchestrate the build. Interrupt handlers, write barriers, interface dispatch trampolines, reading CR3 — each is solved one of three ways.

    

      

        
0

        
lines of C, C++ or assembly

        
As far as we know, no other OS holds this invariant. If a task looks impossible in C#, it's been framed wrong.

        
.c.cpp.h.asm.s

      

      

        
01 / THE LANGUAGE ITSELF

        
Plain C#

        
[RuntimeExport], [UnmanagedCallersOnly], delegate* unmanaged, fixed, pointer arithmetic.

      

      

        
02 / MACHINE CODE FROM C#

        
Iced assembler — at build time and at runtime

        
A source generator bakes 16 early-boot stubs into byte templates; once the heap is up, Iced is called directly.


var a = new Assembler(64);
a.mov(rax, rcx);
a.Assemble(writer, rip);

      

      

        
03 / SYMBOLS FROM ATTRIBUTES

        
COFF objects without a line of C

        
When the linker needs a symbol ILC doesn't emit, an MSBuild task generates the .obj itself.


[BootAsm.CoffDataSymbol("__security_cookie", Section = ".data")]
public static ulong SecurityCookie = 0x2B992DDFA232UL;

      

    

  






  

    
Architecture

    
Three execution tiers

    
From bare metal up to stock .NET assemblies loaded byte-for-byte. A unikernel: one address space, its own scheduler, its own GC.

    

      

        
TIER 0

        
Kernel-AOT

        
Kernel, boot, drivers, scheduler. Direct access to CR3, PCI, MMIO, IDT, local APIC.

        

          
Lives in
OS/

          
Built with
NativeAOT + NoStdLib + MinimalRuntime

        

      

      

        
TIER 1

        
PE-app

        
Freestanding apps: launcher, shell, DOOM, NES emulators. Each one gets its own collector and heap.

        

          
Lives in
apps_native/

          
Built with
NativeAOT + NoStdLib + shared SDK

        

      

      

        
TIER 2

        
CoreCLR-hosted

        
Stock .NET DLLs, byte-for-byte: JIT, reflection, the full BCL. This is how PowerShell runs.

        

          
Lives in
\sharpos\*.dll on FAT

          
Built with
CoreCLR fork, linked into the kernel

Pipes

    
Programs pass objects, not bytes

    
PIPEGEN | PIPEFILT 3 | PIPECNT works just like in bash — but every stage receives a real object with fields. It lives in shared exchange memory: no parsing, no copying into the receiver's heap.

    

      

        
›PIPEGEN 1000LogEntry × 1000

        

        
?PIPESPY a@ 0x7F3A2000

        

        
?PIPESPY b@ 0x7F3A2000

        

        
ƒKQL 'where Level >= 3 | summarize n = count() by Level'

        
Both PIPESPY stages see the same address: one object flows through four programs.

      

      

        

          
0 alloc Zero allocations per message

          
Copy, forward, read in place. On a 100-object graph it's 5–6× faster than BinaryWriter + BinaryReader.

        

        

          
KQL Queries right in the pipeline

          
Kusto Query Language over a message stream: where, summarize, extend, project. The query binds before the first data arrives.

        

        

          
[Message] One attribute and a type can travel


Pipe.Read<LogEntry>()
    .Where(e => e.Level >= min)
    .WriteTo();  // zero-copy

        

        

          
CONVERT JSON, JSON Lines, CBOR

          
Fully streaming, one message in memory: a 100 MiB file passes through a 64 MiB heap.

Quick start

        
Build it yourself

        
It builds with a plain dotnet publish -r win-x64. mise or nix installs the toolchain, and the image boots in QEMU.

        
    
          
  1. Install mise or nixEvery tool version is pinned in mise.toml / flake.lock.
    2. 
          
  2. Clone with submodulesThe CoreCLR fork is optional — skip it with -SkipCoreClr.
    3. 
          
  3. Build and runrun_build.ps1 builds the kernel, makes the image and launches QEMU.
    4. 
          
  4. Drop in payloadsDOOM1.WAD, .nes cartridges and PowerShell go into payloads/.
    5. 
        

      

      

        

          
          
        

        

          


# macOS / Linux / Windows
brew install mise            # or: winget install jdx.mise

git clone --recurse-submodules \
  https://github.com/daniilvaino/SharpOS.git
cd SharpOS
mise trust && mise bootstrap
mise exec -- pwsh

# then, in PowerShell
./build.ps1 launcher
$env:SHARPOS_GUI=1; ./run_build.ps1 -UsbOnly -SkipCoreClr

          

        

        

          


# NixOS or any Linux with flakes enabled
git clone --recurse-submodules \
  https://github.com/daniilvaino/SharpOS.git
cd SharpOS
nix develop --command pwsh

# then, in PowerShell
./build.ps1 launcher
$env:SHARPOS_GUI=1; ./run_build.ps1 -UsbOnly -SkipCoreClr
