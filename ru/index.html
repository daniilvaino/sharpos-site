x86-64 · UEFI · NativeAOT · CC0

Операционная система, целиком написанная на C#.

Загрузчик, ядро, сборщик мусора, драйверы, оболочка и приложения. Ядро, DOOM и оболочка написаны на чистом C#: ни одного файла .c, .h или .asm. Стоковый PowerShell 7 работает поверх этого через опциональный форк CoreCLR: это единственный компонент на C++, и он лежит в отдельном подмодуле.

Инвариант №1

    
Весь исходный код на C#, даже то, что обычно пишут на ассемблере.

    
MSBuild и PowerShell только оркестрируют сборку. Обработчики прерываний, write barrier'ы, трамплины interface dispatch, чтение CR3: всё решается одним из трёх способов. Ярусы 0 и 1, то есть ядро и все нативные приложения, не содержат ни строки на C, C++ или ассемблере. Единственное исключение, ярус 2: стоковому PowerShell нужны JIT и рефлексия, поэтому он работает на опциональном форке CoreCLR. Форк написан на C++ и для сборки и загрузки системы не нужен. Насколько известно, других managed-ОС с таким инвариантом нет: Cosmos на нижнем уровне опускается до X#, собственного диалекта ассемблера, а Singularity держала загрузчик и HAL на C++ и ассемблере. Если задача кажется нерешаемой на C#, значит, она неверно поставлена.

    

      

        
1 · Средства языка

        
Сам C#

        
[RuntimeExport], [UnmanagedCallersOnly], delegate* unmanaged, fixed, арифметика указателей.

      

      

        
2 · Машинный код из C#

        
Ассемблер Iced: при сборке и на лету

        
Source generator превращает 16 стабов раннего старта в байтовые шаблоны. Когда куча поднята, Iced вызывается напрямую.


var a = new Assembler(64);
a.mov(rax, rcx);
a.Assemble(writer, rip);

      

      

        
3 · Символы из атрибута

        
COFF-объекты без единой строки на C

        
Если линкеру нужен символ, который ILC не эмитит, MSBuild-задача сама создаёт .obj.


[BootAsm.CoffDataSymbol(
    "__security_cookie",
    Section = ".data")]
public static ulong SecurityCookie
    = 0x2B992DDFA232UL;

Демо

    
Это не hello world: PowerShell и DOOM на голом железе.

    
Самые требовательные тесты всего стека сразу: TPL, исключения, рефлексия, GC, FAT32, ANSI-консоль, framebuffer.

    

      
      
      
    

  






  

    
Трубы

    
Программы передают объекты, а не байты.

    
PIPEGEN | PIPEFILT 3 | PIPECNT работает как в bash, но каждая стадия получает настоящий объект с полями. Объект лежит в общей памяти обмена: без парсинга и без копирования в кучу получателя.

    

      

        
›PIPEGEN 1000LogEntry × 1000

        

        
?PIPESPY a@ 0x7F3A2000

        

        
?PIPESPY b@ 0x7F3A2000

        

        
ƒKQL 'where Level >= 3 | summarize n = count() by Level'

        
Обе стадии PIPESPY показывают один и тот же адрес: один объект проходит через четыре программы без копирования.

      

      
    
        
  • Ноль выделений на сообщениеКопия, пересылка, чтение на месте. На графе из 100 объектов в 5–6 раз быстрее, чем BinaryWriter + BinaryReader.
    • 
        
  • Запросы прямо в конвейереKusto Query Language над потоком сообщений: where, summarize, extend, project. Запрос связывается до прихода первых данных.
    • 
        
  • Один атрибут, и тип ходит по трубеПометьте тип атрибутом [Message], и его можно читать, фильтровать и писать обратно без копии.

    Pipe.Read<LogEntry>()
    .Where(e => e.Level >= min)
    .WriteTo();  // без копии
    • 
        
  • JSON, JSON Lines, CBORCONVERT работает потоково, в памяти одно сообщение: файл на 100 МиБ проходит через кучу в 64 МиБ.
    •

Быстрый старт

    
Соберите сами

    
Собирается обычным dotnet publish -r win-x64. Зависимости ставит mise или nix, образ запускается в QEMU.

    

      
    
        
  1. Поставьте mise или nix. Все версии инструментов закреплены в mise.toml и flake.lock.
    2. 
        
  2. Клонируйте с подмодулями. Форк CoreCLR необязателен, без него нужен флаг -SkipCoreClr.
    3. 
        
  3. Соберите и запустите. run_build.ps1 собирает ядро, делает образ и запускает QEMU.
    4. 
        
  4. Положите payloads. DOOM1.WAD, картриджи .nes и PowerShell кладутся в payloads/.
    5. 
      

      

        

          
          
        

        

          

# macOS / Linux / Windows
brew install mise            # или winget install jdx.mise

git clone --recurse-submodules \
  https://github.com/daniilvaino/SharpOS.git
cd SharpOS
mise trust && mise bootstrap
mise exec -- pwsh

# дальше в PowerShell
./build.ps1 launcher
$env:SHARPOS_GUI=1; ./run_build.ps1 -UsbOnly -SkipCoreClr

        

        

          

# NixOS или любой Linux с включёнными флейками
git clone --recurse-submodules \
  https://github.com/daniilvaino/SharpOS.git
cd SharpOS
nix develop --command pwsh

# дальше в PowerShell
./build.ps1 launcher
$env:SHARPOS_GUI=1; ./run_build.ps1 -UsbOnly -SkipCoreClr
